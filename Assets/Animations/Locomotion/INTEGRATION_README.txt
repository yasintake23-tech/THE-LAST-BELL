29 FBX 7400 binary animation candidates, baked at 30 FPS. Original animation source: Walk_Forward_unity.fbx. Source hierarchy, skin/proxy and units preserved. 159 curves per file (52 rotation tracks and hips translation). Procedural inverse-kinematics authoring, not motion capture. Source skeleton sampled visually in six contact sheets and checked numerically; no Unity import, mesh, collider, or APK test performed. Skeleton_Preview.png is a joint-only visual, not a game screenshot.

IMPORTANT: DO NOT overwrite previous clips or automatically activate all clips. V2 clips are alternatives. In particular Fall_Forward_V2 and Get_Up_V2 are experimental contact-sequence prototypes, Flashlight_Run_V2 is fast gait without a true flight phase, and Flashlight_Pickup_V2 requires live target validation. Keep these in debugger until visually approved. Other clips also require runtime validation.

The target model.fbx has a different skeleton: Hips/Spine/Spine1/Spine2, Neck/Neck1/Neck2, LeftArm/LeftForeArm/LeftHand, RightArm/RightForeArm/RightHand, LeftUpLeg etc. Source has Hips/Spine/Chest/UpperChest, LeftUpperArm/LeftLowerArm and corresponding named bones. Only 10 model names match exactly. Use a valid Humanoid Avatar for each skeleton, verify T-pose, bone mapping, extra twist bones, scaling, and retargeted foot height. Do not use the proxy mesh as the player. Do not use Copy From Other Avatar across nonmatching skeletons unless verified.

Grounded movement: use velocity-driven locomotion. Stationary crouch = Crouch_Idle_V2 or Flashlight_CrouchIdle_V2. Crouch locomotion only when velocity is nonzero. Loop only entries marked loop in manifest.json. Match gameplay speed to recommended clip speed (m/s on source skeleton) and validate actual retargeted stride. Controller motion and root motion must not double. Turn clips contain visual hips yaw, not a separately animated controller root; coordinate controller rotation.

Flashlight: attach the physical light to target avatar RightHand socket calibrated to the real flashlight handle, not independently to camera. Apply IK after base pose. Use right arm mask for raise/lower/release and avoid duplicate full-body and mask transforms. For arbitrary aiming use dynamic IK, not static look clips. The look clips can be head/neck/upper chest masked reference poses; runtime pitch and yaw tracking should be anatomical. Door and wall clips require live contact IK. Event times in manifest are suggested seconds, NOT embedded FBX events; bind AnimationEvents or state events in Unity after visual validation. Fall release/impact/pickup need collision and physics validation.

FPP: keep body, legs and hands visible; selectively hide head/obstructive geometry; maintain TPS mesh and shadows. Lighting/debug inspection requires Unity changes, not animation files.

Ground diagnostic values in manifest are source skeleton joint positions only, not sole or skin contact. Some source ankle/toe targets remain above nominal ground because shoe geometry is not measured. Do not infer no penetration on target mesh from these numbers. Use neutral lighting and inspect every candidate in first-person and third-person before enabling in live gameplay.
